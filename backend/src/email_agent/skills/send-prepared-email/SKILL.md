# 发送已准备邮件

## 适用条件

- 用户明确要求发送，并且收件人、主题和完整正文已在当前请求或可信上一步草稿中确定。
- 如果仍需要润色、补全或推断正文，应先使用草稿工作流，不能使用本 Skill。

## 输入规则

- `to`、`subject`、`body` 必须非空，抄送和密送仅使用用户明确提供的地址。
- 必须使用服务端生成或恢复层提供的幂等键。
- 初次工具调用时 `approval_token` 必须为空。

## 执行流程

开始前必须调用 `prepare_skill_workflow` 获取发送工作流的服务端安全说明。

1. 核对上一步草稿或当前请求中的最终字段，缺一项就停止。
2. 委派 `mail-writer` 调用 `send_email`。
3. 等待 DeepAgents interrupt 和服务层审批；批准后由可信 API 层注入一次性凭证恢复。
4. 使用 `merge_subagent_results` 保留真实发送状态。

## 安全边界

- 只能通过 `task` 委派 `mail-writer`。
- 不得自行生成审批凭证、修改审批后的内容或通过其他工具绕过审批。
- 不得把草稿、待审批、中断或错误结果描述为已发送。
- 不得在结果不确定时自动重试并产生重复邮件。

## 空结果

- 任一必填字段为空时返回 `failed`，不得调用发送工具。
- 没有明确发送意图时只保留草稿。

## 上游失败

- 审批拒绝、过期、内容不匹配或 Provider 失败时返回 `failed`。
- 只有工具返回 `status=sent` 和消息 ID 时才能确认发送成功。

## 结果要求

- 成功时包含收件人、主题和消息 ID，不重复展示不必要的完整正文。
- 失败时说明邮件未发送，并保留安全的失败原因。
